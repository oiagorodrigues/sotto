# Decision log

Small and ad-hoc decisions, newest last. Anything expensive to reverse becomes an ADR in `docs/adr/`. Every agent working on Sotto reads this file and the "Lessons" section before starting, and appends here when it makes a call that a later reader could get wrong.

Entry format: date, decision, why, and what would make us revisit it.

## Lessons (read first)

These are mistakes already made, or traps already found. Do not repeat them.

1. WWDC25 sample code for SpeechAnalyzer does not match SDK 27: `deallocate(locale:)` is now `release(reservedLocale:)`, and the presets `.offlineTranscription` and `.progressiveLiveTranscription` are gone. The SDK `.swiftinterface` is the source of truth.
2. `AssetInventory.status(forModules:)` returned `.supported` while `pt_BR` was listed in `installedLocales`. Always call `assetInstallationRequest(supporting:)`, which returns nil when nothing is missing, instead of trusting `status`.
3. Volatile transcription results can be revised or revoked (empty text over a range). Never trigger irreversible actions on a partial.
4. Ending the input `AsyncStream` does not end an analyzer session. Call one of the `finish*` methods.
5. `SpeechTranscriber` has no punctuation option. Do not build detection on question marks.
6. `SpeechDetector` results only report VAD errors; it cannot mark end of speech.
7. Never add a directory to `PATH` to find a helper binary. Launch helpers by absolute path inside the bundle.
8. Never drop data silently under load. Bound the queue and count overflow.
9. Never zero the mic while the other side speaks to fight echo. Use voice processing echo cancellation.
10. Never load scripts or models from a CDN at runtime, even as a fallback. Bundle them, or download with a pinned SHA-256.
11. Never accept an auth token from a deep link without a state check (ADR 0008).
12. Never apply an unvalidated object from the UI to app state.
13. `whisper-rs` is archived on GitHub; `tauri-nspanel` has a single maintainer and no releases; `specta` is still a release candidate. Check maintenance status before adding a dependency.
14. The crates.io API was blocked in this environment; use `gh api` for GitHub data and the GitHub advisory database (`/advisories?ecosystem=rust&affects=<crate>`).
15. serde's `deny_unknown_fields` does not apply to unit variants of an internally tagged enum: `{"type":"stopped","extra":1}` deserializes into `Stopped`. Write every variant as a struct variant (`Stopped {}`); the JSON without fields still parses. ts-rs prints a harmless "failed to parse serde attribute" warning for `deny_unknown_fields`.
16. `SpeechTranscriber` volatile results keep the same range start while growing, and a final can cover less than the last volatile (en-US: volatile ended at 8740 ms, the first final at 3960 ms), so the next volatile starts at the final's end. The segment mapper keys a segment on "open until a final", not on identical ranges. A final for a pt-BR clip also started at 120 ms while its first partial started at 0.
17. In the sidecar, a `DispatchSourceTimer` handler that does `queue.sync` on its own queue traps with `EXC_BREAKPOINT` in `__DISPATCH_WAIT_FOR_QUEUE__` and no message on stderr (exit 133). Use a lock instead of `sync` from inside the queue.
18. `swift test` in this package uses Swift Testing (`import Testing`), which ships in the Command Line Tools, but see Lesson 22 before relying on them. A test can find the built executable next to the `.xctest` bundle (`Bundle.allBundles`).
19. `-sectcreate __TEXT __info_plist` works from `linkerSettings: [.unsafeFlags([...])]` with a package-relative path (`Support/Info.plist`); `otool -s __TEXT __info_plist` shows it. Keep the plist outside `Sources/` or SwiftPM reports it as an unhandled file.
20. `SpeechTranscriber.installedLocales` identifiers: use `locale.identifier(.bcp47)` to get `pt-BR`; the default `identifier` is `pt_BR`.
21. serde_json error messages quote the offending value (`invalid type: string "...", expected u64`), so the `reason` of `SidecarOutput::BadLine` can hold transcript words even though the line itself is dropped. Never log it.
22. With the Command Line Tools toolchain, SwiftPM's default build system fails the first build of a Swift Testing target after any other build configuration (a release build, or different `-Xswiftc` flags) with "plugin for module 'TestingMacros' not found"; a retry passes, so it looks flaky. `--build-system native` cannot find `Testing` at all. Xcode 27.1's toolchain (`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`) does not fail. The `justfile` exports that `DEVELOPER_DIR` and builds the warnings-as-errors check in its own `--build-path .build/strict`.
23. A Tauri event emitted before a webview has called `listen` is lost, and `on_page_load(Finished)` fires before React effects subscribe. With an idle core that emits nothing afterwards, the transparent overlay and notch rendered an empty root, so the app showed a Dock icon and no visible window. Views must pull the current state once after subscribing (the read-only `current_snapshot` command); never rely on a replay timed to page load.
24. wiremock matches requests against mocks in the order they were mounted, so mount the specific matcher (for example a body containing `grant_type=refresh_token`) before a catch-all for the same path, or the catch-all answers first.
25. `sqlx` and `rusqlite` cannot share a Cargo workspace. Cargo resolves optional dependencies for the lockfile, so `sqlx` pulls `sqlx-sqlite` and `libsqlite3-sys ^0.30`, which `links = "sqlite3"` like the `libsqlite3-sys 0.35` behind `sotto-core`'s `rusqlite`, even with `default-features = false` and no sqlite feature. `services/api` is therefore its own workspace (own `Cargo.lock` and `target/`) and the root `Cargo.toml` excludes it. The `justfile` runs its fmt, clippy and tests with `cd services/api`.
26. Sidecar file mode (and a normal session) downloads and installs a missing speech model on its own (`assetInstallationRequest(...).downloadAndInstall()`), with no consent step and no progress event. The onboarding check therefore reads `installed_locales` from the helper's `Ready` and stops before the clip when the locale is missing, instead of letting a benchmark trigger a multi-hundred-megabyte download.
27. Loading app state asynchronously and then replacing the in-memory copy when the load finishes wipes anything created in between: a modes test that created a mode right after start failed about one run in ten. Read what the event loop needs before the storage thread takes the database, and build the first snapshot from it.
28. A `start_paused` tokio test that waits on a real thread (the storage thread) lets virtual time jump to the next timer while the thread works, so timeouts fire early. The modes tests run on real time.
29. `/api/tags` reports `digest` as the full 64-character SHA-256 of the model manifest; `ollama list` shows only its first 12 characters as `ID`. Compare the full value.
30. `pdf-extract` 0.12.1 pins `lopdf` 0.42 exactly, which is the first release after the nested-array stack overflow (GHSA-6fj4-rcr3-r7rr, "cannot be caught with `catch_unwind`"). Do not loosen that pin to an older lopdf.
31. OpenAI's live transcription model `gpt-live-transcribe` takes no server VAD (`turn_detection` must be `null`) and returns the final text only when the client sends `input_audio_buffer.commit`. A client that sends a continuous stream and waits for a final never gets one. The client has to cut turns itself (`cloud_stt/gate.rs`).
32. Tests that use real sockets cannot use `#[tokio::test(start_paused = true)]`: with paused time the runtime auto-advances the clock while it waits on the loopback, so connect and handshake timeouts fire at once. The cloud tests in `app/tests/cloud.rs` run in real time and put the session clock where they want it with `Started.emitted_at_ms`.
33. OpenAI's docs disagree with themselves about the transcription endpoint: the model page lists only `v1/realtime/transcription_sessions`, while the transcription guide connects to `wss://api.openai.com/v1/realtime?intent=transcription` and sends `session.update` with `session.type: "transcription"`. The core follows the guide; the model page's endpoint was not tried (no paid calls in this slice).
34. A wait on "cloud available" returns at once for a signed-in account, because hosted tokens count as credentials. A test that saves an OpenAI key and then starts a session must also wait for the provider to show as configured, or the hosted source is used and the test flakes under load.

- **Detector design (2026-11-06, `sotto-detect`):** the question score is a sum of weighted lexical features per clause (best clause wins, `?` adds 0.25), threshold 0.5, dropped below 0.25. Turn stability is measured on the normalized text, not on `is_final` or on revisions that only add punctuation, so a late final does not re-arm `TurnEnded`; changed words do re-arm it, so a speaker resuming within `max_turn_gap_ms` gets a second `TurnEnded` for the same turn. ### 2026-11-06 (sotto-core infrastructure)

- **SQLCipher through `bundled-sqlcipher-vendored-openssl`.** It builds OpenSSL from source, so the result does not depend on a Homebrew OpenSSL that may move. The build worked on the first try; the `Db` test proves the cipher is active (a wrong key and a plain SQLite open both fail, and the file holds no plaintext). Revisit if the OpenSSL build time hurts CI.
- **Database key is passed as a raw key (`PRAGMA key = "x'<64 hex>'"`).** It skips the passphrase KDF, which is right for 256 random bits from the Keychain. A passphrase would need the KDF.
- **Purge hard-deletes.** `purge_sessions_older_than` removes sessions and their segments and answers with `ON DELETE CASCADE`; `delete_session` is the soft tombstone. A tombstone alone would leave meeting text on disk, which defeats retention.
- **Revoked transcript segments (empty text) are tombstoned, not deleted,** and a later non-empty revision of the same segment restores them. Only a higher `revision` replaces a stored one.
- **Anthropic wire details.** `anthropic-version: 2026-10-21` (from the bundled API docs). Cache breakpoint on the mode-context block, or on the system prefix when the mode context is empty. `effort` goes in `output_config`; no `temperature`, `top_p`, `thinking` or prefill is ever sent. The refusal category is read from `delta.stop_details.category` on `message_delta`; this location is inferred from the docs' non-streaming `stop_details` shape and is unverified against a live stream. A refusal yields a `Usage` event and then an error, never a `Done`.
- **`StreamEvent::Usage` is a struct variant as specified,** and a separate `Usage` struct carries the same four fields for storage and pricing (`StreamEvent::usage()` converts).
- **Time to first token** comes from `LlmProvider::stream_timed`, which returns the stream plus a `TtftHandle` (request start `Instant` and first `TextDelta` `Instant`). `stream` keeps the plain signature from the spec.
- **OpenAI sends `max_completion_tokens`** (newer models reject `max_tokens`) and ignores `effort`. Cached prompt tokens are split out of `prompt_tokens` into `cache_read_input_tokens` so `input_tokens` means uncached input for every provider.
- **Pricing cache-write prices** use the 5-minute multiplier (1.25x input). The Haiku 5.5 cache-read price (10% of input) is an estimate, marked in `config/pricing.toml`. OpenAI prices are 0 until the user fills them in.
- **`crates/sotto-core/clippy.toml` allows `unwrap`/`expect` in tests** so `-D warnings` with `--all-targets` keeps the `unwrap_used` rule for library code only.

### 2026-11-06 (sotto-core orchestrator, `crates/sotto-core/src/app`)

- **One task owns all state and never awaits in a handler.** SQLite runs on its own thread behind an unbounded queue (transcript revisions must not be dropped, and speech bounds their rate); sidecar writes go through a writer task because `SidecarProcess::send` can wait up to 5 s on a full pipe; provider calls run in tasks that report over one channel tagged with a stream id. A `Running` handle cancels its stream on drop, so clearing or replacing an answer always stops the work. Messages from a stream that is no longer the live one are ignored, except `Usage`, which still counts toward spend because those tokens were billed.
- **`Db::create_session_with_id` and `Db::insert_answer_with_id` added** so the ids in the snapshot are the database ids without waiting on the storage thread.
- **Automatic answers are stored only when revealed.** Cancelled speculations leave no row; their cost shows in `spend_micro_usd`. A restart counts as one cancel plus one start, and it re-runs the classifier on the new text, so a restart at turn end waits for a fresh verdict.
- **Classifier verdicts:** anything other than "yes" (including a failed call) means "not confirmed" and cancels the speculation; a failure also sends a `Notice`. A setup failure (missing key, unknown model) on either call shows a `Failed` answer at once, because every later answer would fail the same way. Runtime errors in a hidden answer stream are held and shown only if the answer is revealed. The ADR 0006 rule "local Ollama classifier only when warm" is not implemented; the classifier uses `Settings::classifier_model`. Revisit when Ollama is offered in settings.
- **One live answer:** a new likely question replaces a hidden speculation for another turn but never a visible answer still streaming (manual or revealed). Discarding a speculation shows the previous finished answer again.
- **Latency stats (`last`/`p50`/`p95`) count automatic answers only,** nearest-rank, per session; manual asks keep their time to first token from the intent in `AnswerView::latency_ms` and storage (ADR 0006 reports cold answers separately). Debug counters reset at `StartSession`.
- **The transcript goes into `CompletionRequest::mode_context`** after the mode text, so the Anthropic cache breakpoint covers it. For automatic answers it excludes the question turn (the trailing run of "them" lines the tracker would join). The transcript is not truncated; revisit if long meetings push prompts past a model's context or the spend cap.
- **Model ids:** `claude-*`, `gpt-*`/`o<digit>*`, and `ollama:<name>`. `DefaultProviderFactory` keeps one provider per family while the key is unchanged, so the HTTP connection pool (and TLS session) survives between answers. The Keychain read happens in the stream task: it can block a runtime worker briefly, never the loop.
- **Errors outside answers go to `AppHandle::notices()`** (a broadcast channel) because `AppSnapshot` has no error field and the contract was not to change. After the sidecar exits mid-session the session stays `Listening` with `engine: Unavailable`; there is no automatic respawn, and the next `StartSession` spawns a new sidecar.
- **`Settings` are read once at `App::start`** (no settings intent in the contract yet), the initial phase is `Idle` (onboarding is the shell's call), and `OpenSettings` is a no-op in the core. `dispatch` never waits: it uses `try_send` on a 256-slot queue and returns `Busy` when full.
- **The screenshot wait is checked on the 50 ms tick,** so the 3 s timeout can run up to 50 ms late. The base64 PNG is decoded in the stream task, off the loop.

### 2026-11-06 (sidecar review fixes)

- `Started.emitted_at_ms` is `HostClock.elapsedMsNow()` taken right before the line is written, clamped at 0. The core derives t0 from it (item 3). Revisit if events are ever buffered between creation and write.
- `Session.failStart` is the single exit for start failures: `stop()` then a fatal error, never `exit`. Not-fatal on purpose: "session already running" and "no speakers", which do not touch session state.

### 2026-11-06 (slice 1 review: core fixes)

These replace three earlier entries: "Locale is still `Settings::default()`", "OpenAI prices are 0 until the user fills them in", and the "no `thinking` is ever sent" part of "Anthropic wire details".

- **`StreamEvent::Usage` is an increment, not a total** (item 1). Anthropic emits input and cache tokens at `message_start` and the output at `message_delta`; consumers sum every event of a stream. A stream that ends without its final usage (cancelled, cut off, failed mid-stream) gets an estimate from the stream task: four bytes per token for the prompt when no input was reported, and for the text received minus the output already reported. It is billed at the uncached input price, which overcounts on purpose, because the estimate feeds a spend cap. An HTTP error before the stream opens bills nothing. Revisit if the providers start reporting usage on cancel.
- **No price, no automatic answers** (item 2). `PriceTable::is_priced` needs input and output above zero. The OpenAI entries at 0 are gone from `config/pricing.toml` instead of getting invented prices. When the auto or classifier model is unpriced, the speculation does not start, `last_guard_block` says `no price for <model>`, and one notice per session says "Set a price for <model> to use automatic answers". Ollama is exempt. `<data_dir>/pricing.toml` (same format, `as_of` optional, every model needs all four prices) is read once at `App::start` and replaces bundled entries per model; an invalid file is ignored with a start notice. `AppConfig` gained `data_dir: Option<PathBuf>` and `AppConfig::new(...)`.
- **t0 is `now - emitted_at_ms`** on `Started` (item 3), with `checked_sub` falling back to now.
- **Thinking per request** (item 4). `CompletionRequest::thinking` is `Adaptive` (send nothing) or `Disabled`. The classifier is `Disabled` with effort low and `max_tokens` 256: Anthropic `thinking: {type: "disabled"}`, OpenAI `reasoning_effort: "minimal"` with `max_completion_tokens` floored at 512 on reasoning models (`gpt-5*`, `o<digit>*`; `gpt-4o` gets no `reasoning_effort`), Ollama `think: false`. Answers stay adaptive at low effort with `max_tokens` 1,024 (auto) and 4,096 (manual). A `max_tokens`/`length` stop with no text is `ProviderError::NoTextAtTokenLimit`, which fails the answer with "The model spent its whole output budget reasoning...". Revisit if the classifier ever needs more than one word.
- **Start failures end the session** (item 5). A fatal sidecar error before `Started`, the sidecar exiting before `Started`, or no `Started` within 10 s ends the session with engine `Unavailable` and a notice. The fatal-error case ends at once instead of waiting 10 s, since `Started` cannot follow it. On the timeout the core also drops the sidecar link, so the next start spawns a fresh helper.
- **`Start` waits for `Ready`** (item 12). The core needs the installed list to pick the locale, and the sidecar sends `Ready` on launch, so `Start` goes out when `Ready` arrives (immediately if this helper already sent it). `OpenSettings` also starts the helper so the language list is known before the first session. The 10 s start timeout covers a helper that never sends `Ready`.
- **Locale** (item 12). The order is the saved `locale` setting while it is installed, then the system locale when installed (case-insensitive match), then `en-US`. The system locale is `AppleLocale` from `/usr/bin/defaults` (absolute path), else `LC_ALL`/`LC_MESSAGES`/`LANG`, read once in `App::start` when `Settings::system_locale` is `None`. `SetLocale` checks the BCP 47 shape in the protocol and the installed list in the core (rejected with a notice when the list is known and lacks it); it applies to the next session. Revisit if a region-only mismatch (`en-BR` on an English system set to Brazil) should fall back to the language (`en-US`) instead of `en-US` by default.
- **Screen Recording** (item 6). The first screenshot ask of an app run sends `RequestPermission { screen_recording }` before `CaptureScreenshot`. A `permission_denied` error while a shot is pending is that shot's failure (the sidecar entry above explains why) and answers at once without the image.
- **Retention purge** (item 7). `Settings::retention_days` (default 30, `None` keeps everything, saved as `retention_days`, a number or `null`) is applied by the storage thread when the loop starts and every 24 h after.
- **Transcript events before `Started` are dropped** (item 8): they are finals the helper flushes for the previous session.
- **Only automatic spend counts toward the cap** (item 10). Usage messages carry the job kind; manual asks add to `spend_micro_usd` in the debug stats but not to the guard. `DebugStats::last_guard_block` keeps the last reason (cooldown, rate limit, spend cap, no price) for the session.
- **Keys are cached in memory** (item 11). `CachedStore` wraps the secret store inside `App::start`: the first read of each account reaches the Keychain, `SetApiKey`/`RemoveApiKey` update the cache, a failed write drops the entry. A key changed outside the app is seen after a restart.
- **Cache breakpoints** (item 14). `CompletionRequest` splits the context into `mode_context`, `history` (transcript lines up to the first non-final one) and `recent`. Anthropic marks the last stable block before the transcript and the `history` block, each only when the estimated prefix up to it reaches the model minimum: 512 tokens for the 5.5 models, per the bundled API reference (cached 2026-10-06, which itself says to check the live docs), and 4,096 for unknown models. `recent` is never marked. OpenAI and Ollama get the three parts joined. Revisit when the live caching docs list 5.5 minimums.
- **30 s idle timeout between stream chunks** (item 13), `ProviderError::IdleTimeout`.
- **Keychain notices redact the key** (item 16): the test store now echoes its input, and the save error text has the key replaced with `<key>`.
- **`auto_answer` is saved** (item 19) and read at start like the models.
- **Lesson for tests:** with paused tokio time, `sleep_until` steps through every 50 ms core tick, so reaching 24 h that way is millions of iterations. `tokio::time::advance` jumps in one step and an interval with `MissedTickBehavior::Delay` fires once.

### 2026-11-06 (slice 2: backend)

- **`services/api` is a separate Cargo workspace** (Lesson 25). The root `Cargo.toml` only gains `exclude = ["services/api"]`. Its lints are copied from the root. `just api-check` (fmt, clippy, tests) runs inside `just rust`, so `just check` covers it. Revisit if `sotto-core` moves off `rusqlite` or sqlx drops its sqlite dependency from the lockfile.
- **API tests are `#[cfg(test)]` modules in the crate, not `tests/`.** The workspace-wide `unwrap_used` deny only has an exception for test code through `clippy.toml`, and that exception does not cover helper functions in an integration test crate. They use `#[sqlx::test]`, which creates a throwaway database per test from `DATABASE_URL` (Postgres from `docker-compose.yml`, user `sotto` is a superuser).
- **Sign-up is a mailed link, not an immediate login.** A form that signs a new address in at once must answer differently for an address that already has an account, which enumerates users. Sign-up, "email me a link" and sign-in by link all store a hashed single-use link (15 minutes); the account is created when the link is opened, and a password hash carried by the link is only used if the account does not exist yet. A sign-up for an existing address therefore sends a normal sign-in link and never changes the password. Cost: first sign-up needs one email round trip. Password sign-in does a dummy Argon2 verify for unknown addresses.
- **After a form post the server answers 200 with a "Return to Sotto" page (meta refresh plus a link), not a 303 to `sotto://`.** The required CSP has `form-action 'self'`, and Chrome applies `form-action` to redirects after a form submission, so it would block the redirect to the custom scheme. The link works in every browser because link navigation is not covered by `form-action`. The magic link (`GET /magic/{token}`) uses the same page for one code path. Unverified in a real Chrome and Safari; check with the desktop client. Revisit if a browser blocks the meta refresh (the button still works).
- **Magic links complete on a plain GET,** as specified. Mail scanners that prefetch links can spend a link before the user clicks it; the user then requests another. A confirm button would fix it at the cost of one more click.
- **Auth codes are spent before the PKCE check,** so a wrong verifier burns the code. Presenting a spent code again revokes the token family it produced (RFC 6749 section 4.1.2).
- **Refresh tokens rotate and a replayed one revokes the family.** Access tokens already issued from that family stop working at once because every request checks `token_families.revoked_at`. Access and refresh tokens are 32 random bytes (base64url), stored as SHA-256.
- **Rate limits.** Sign-in, mail and token limits are in memory (per process, sliding window). Defaults: sign-in 20 per IP and 10 per email per 10 minutes, mail 20 per IP and 5 per email per hour, token endpoint 60 per IP per minute. A per-email sign-in limit lets someone lock a victim out for 10 minutes; accepted because the alternative is unlimited guessing. The client IP is the TCP peer, so behind a proxy all clients share one IP until a trusted forwarded header is added. Realtime tokens (20 per account per hour) are limited by counting rows in `realtime_token_audit` under a per-account advisory lock, so the limit survives restarts and holds across instances.
- **Password rules:** 10 to 128 characters, no composition rules. Argon2id with m=19 MiB, t=2, p=1 (OWASP minimum). `[profile.dev.package.argon2]` is optimized, otherwise each hash takes seconds in tests.
- **Preferences are a typed document with a version.** `PUT` needs `base_version` equal to the stored version; a stale write gets 409 with the current document. Body limit 64 KiB, at most 100 modes, 8,000 characters per prompt.
- **OpenAI hosted mode.** `POST {OPENAI_BASE_URL}/v1/realtime/client_secrets` with the server key and `{expires_after: {anchor: created_at, seconds: 600}, session: {type: transcription, audio: {input: {format: {type: audio/pcm, rate: 24000}, transcription: {model, language}}}}}`; the response `value` and `expires_at` (Unix seconds) become the token. Sources: https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets/methods/create and https://developers.openai.com/api/docs/guides/realtime-transcription. The reference page gave the request schema but its response example was marked illustrative, and the two pages name different transcription models (`gpt-transcribe` and `gpt-live-transcribe`). The model is the `OPENAI_TRANSCRIBE_MODEL` env var, default `gpt-live-transcribe`. Unverified against the live API (no paid calls were made); tests use a fake upstream. An upstream error returns 502 and logs only the status code.
- **Logs:** the trace layer records method, matched route (never the URI or query), status and latency. Nothing logs bodies; serde errors are not echoed to clients because they quote values.
- **No CORS layer at all,** so no `Access-Control-*` header is ever sent. Security headers (CSP from the task, nosniff, no-referrer, `X-Frame-Options: DENY`, `Cache-Control: no-store`) apply to every response. The CSRF cookie is `HttpOnly; SameSite=Strict; Path=/authorize` and `Secure` when `PUBLIC_BASE_URL` is https.
- **Compose:** Postgres 18 mounts its volume at `/var/lib/postgresql` (the 18 image changed the data path). The `api` service is behind the `full` profile so `docker compose up -d --wait postgres mailpit` and `just api-up` never build it.

### 2026-11-06 (slice 2: modes and retrieval)

- **Embedding model: `nomic-embed-text-v2-moe`** (ADR 0011). Measured on this Mac (M4 Pro, Ollama 0.40.14) with 12 pt-BR and English passages and 12 questions, including cross-language ones (`crates/sotto-rag/tests/ollama_live.rs`, run with `--ignored --nocapture`): top-1 and top-3 were 11/12 and 12/12 for nomic, 11/12 and 12/12 for bge-m3, 10/12 and 12/12 for embeddinggemma. Warm query latency was 9 to 90 ms for all three. Indexing 64 chunks of 1,200 bytes in batches of 16 took 1.5 s for nomic and embeddinggemma and 3.0 s for bge-m3. Sizes on disk: 958 MB, 1.2 GB and 622 MB. The sample is small, so the three models are not separated by quality; the decision rests on speed, license (embeddinggemma ships under the Gemma terms of use) and size. Not measured: a cold model load (the first call took 13 to 106 ms, but the models may already have been resident) and quality on real documents.
- **Retrieval floor, top-k and budget.** Unrelated questions scored at most 0.235 against the sample passages and matching ones at least 0.351, so the minimum cosine is 0.3. Top 6 chunks, at most 3,000 estimated tokens. Provisional; revisit with real documents.
- **Chunks of 320 estimated tokens with 48 overlap.** The model's context is 512 tokens and Portuguese tokenizes worse than bytes / 4 assumes, so 320 leaves headroom. `truncate: true` is set on every embed call as a second guard.
- **Full text up to 30,000 estimated tokens** (from `docs/design.md`). Limits: 10 MB per file, 25 files and 4 million estimated tokens per mode, 50 modes. They bound memory (13,000 chunks at 768 floats is about 40 MB in the session index) and indexing time (about 5 minutes at 44 chunks per second).
- **Retrieved passages travel with the question, not in the mode block.** The cached prefix is system prompt, mode block, transcript history. If the passages sat in the mode block, every new question would change bytes before the history and invalidate its cache, which costs prefill time on long meetings. The mode block holds the instructions and, for small modes, the full text, and is identical for every request of a session.
- **The mode is chosen once per session.** `StartSession { mode_id }` wins; with `None` (the global shortcut sends it) the core uses the mode selected for the next session, which is persisted in the `selected_mode` setting. Editing the running session's mode rebuilds its context for later answers; deleting it leaves the session's context alone.
- **Modes and files are read before the storage thread starts.** See Lesson 27. Every write after that goes through the storage thread with the ids the event loop already shows, so the UI never waits for the database.
- **Query embeddings are cached per session context and limited to 800 ms.** An automatic answer that cannot get its question embedded in time uses the start of each file and shows one notice (repeated notices with the same text are suppressed until retrieval works again).
- **Indexing is one job at a time, in batches of 16, with progress per file.** A file removed or replaced cancels the running job for its mode; the job's late write is refused when the file is no longer live. Files left in `Failed` are retried at the start of the next session and by `RetryIndexing`.
- **Tombstones carry no content.** Deleting a mode or file keeps id, name and timestamps for later sync and blanks the prompt, file text and embeddings.
- **Adding a file with a name the mode already has replaces it.** Re-adding an updated document is the common case, and two files with one name are indistinguishable in the list and in the prompt.
- **File names in prompts are sanitized** (no control characters, `<`, `>`, `"` or `&`, at most 120 characters) because they sit inside a `<file name="...">` tag.
- **Native file panel through `rfd` 0.17.2** (MIT, pushed 2026-10-25, no advisories) with default features off. It opens from `commands::dispatch` on `PickModeFiles`, so no dialog plugin or capability exists and `config_tests` is unchanged. The panel and its focus behavior are not covered by tests (hand check).

### 2026-11-06 (slice 2: account)

- **Deep link through Tauri's own `RunEvent::Opened`, no plugin.** tao already implements `application:openURLs:` and Tauri surfaces it as `RunEvent::Opened { urls }` (tao 0.37.2 `app_delegate.rs`, tauri 2.12.5 `app.rs`). `tauri-plugin-deep-link` would add a dependency and a capability permission for nothing on macOS, and the `kAEGetURL` route through objc2 would repeat what tao does. The scheme is registered by `CFBundleURLTypes` in `src-tauri/Info.plist` (a config test pins it to `sotto` only). The shell forwards `sotto://auth/callback…` to `CoreHandle::deep_link` and logs any other link by scheme only. The three-command and no-plugin config test is unchanged.
- **Unverified: `just dev` does not receive the callback.** LaunchServices maps `sotto://` to a bundle on disk that declares the scheme, and `pnpm tauri dev` runs the bare binary from `target/debug`. Expect the browser to open the "Return to Sotto" page and nothing to happen in the app. To test the full loop, build the bundle (`pnpm tauri build --debug --bundles app`), launch that `.app` once so LaunchServices registers it, then sign in. I could not run either here.
- **The backend URL is a build-time value.** `SOTTO_API_URL` is read with `option_env!`; debug builds default to `http://localhost:8080`; a release build without it has sign-in disabled and the Account page says so. A run-time variable would let anything that sets the environment point the login page, and the code exchange, at another server. `BackendUrl` only accepts https, or http for localhost, `127.0.0.1` and `[::1]`, with no path or credentials. The shell's opener (`backend.rs`) opens only that origin's `/authorize`, and the calendar's `https://`-only opener is untouched.
- **A callback with the wrong state is ignored without ending the login,** the same rule as the calendar loopback listener, so a stray `sotto://` link cannot cancel a sign-in. A matching state is consumed on first use (the pending login is taken before the exchange), so a replay finds nothing. `state` is compared in constant time, though the comparison is against a value the sender already has to know.
- **One task owns the tokens and does its HTTP inline.** Refresh must be serialized (a replayed refresh token revokes the family), so the account task awaits each request in its loop instead of spawning them. The cost is that a command waits up to the 15 s request timeout behind a slow call. The new refresh token goes to the Keychain before the access token is used; if the write fails the access token is dropped and the old (now rotated) token fails with `invalid_grant` next time, which signs out.
- **`invalid_grant` on a refresh signs out locally** and shows "Your session ended"; 5xx, 429 and network errors keep the session and show a sync error, retried by the next sync (10 minutes) or "Sync now". A 401 forces one refresh and one retry; a second 401 is reported, not looped.
- **Preference merge: last writer wins per field.** The task keeps the time each synced setting was last changed on this device (in memory). When a server document arrives (pull or 409), a field changed here after the document's `updated_at` keeps the local value and is pushed; every other field takes the server value. Cost: the device clock is compared with the server clock, so a skewed Mac can lose or win wrongly by its skew; and a change made before a restart but not yet pushed (2 s debounce) is lost, because the stamps are not persisted. A pull on first run with no local edits always takes the server document. The 409 retry loop gives up after 3 rounds and reports it.
- **Synced now: the six settings the core owns** (auto-answer model, manual model, spend cap, locale, auto-answer, invisible). `engine_preference`, `shortcuts` and `modes` are carried through from the last server document untouched (`account/prefs.rs`, `compose`), with `"local"` and empty values for a new account. When the cloud-transcription branch adds an engine preference, and when modes and shortcuts exist in the core, add them to `LocalSettings`, `Field`, `merge` and `compose`, and to `account_settings` and `apply_remote_settings` in `app/event_loop/account.rs`.
- **Remote values are validated like their intents** before the core applies them (known model ids, spend cap at most the maximum, BCP 47 locale), so a document written by another client cannot put the app in a state the settings page cannot produce. `invisible` is applied to the running state but, like the existing intent, not saved to the database. The locale pushed is the resolved one (saved choice, else system, else `en-US`), so the first push pins a locale the user never chose.
- **`email` is in the snapshot,** which every window receives, but only the Settings page renders it.
- **Disabled account:** with no backend address the task does not run and the view starts in the error state with "Sotto sign-in is not available in this build".
- **Not covered by tests:** the real `open` call, the Keychain-backed store, macOS delivering a URL event to a bundle, and the Account page in a browser (no `node_modules` here; `pnpm install` was denied in this sandbox).

### 2026-11-06 (slice 2: cloud transcription)

Sources, all read on 2026-11-06: https://developers.openai.com/api/docs/guides/realtime-transcription (endpoint, `session.update` shape, 24 kHz PCM, events), https://developers.openai.com/api/docs/guides/realtime-vad (`gpt-live-transcribe` needs `turn_detection: null` and a client commit), https://developers.openai.com/api/docs/guides/voice-websockets (`Authorization: Bearer`, no `OpenAI-Beta` header, ephemeral tokens), https://developers.openai.com/api/docs/guides/realtime-conversations (60 minute session limit, 15 MB per append), https://developers.openai.com/api/docs/models/gpt-live-transcribe and https://developers.openai.com/api/docs/pricing (prices). ADR 0010 holds the provider and protocol decision.

- **Model `gpt-live-transcribe`, not `gpt-4o-mini-transcribe`.** The docs recommend it for streaming: it sends deltas while the person speaks, which the question detector needs (ADR 0006). The `gpt-4o-*` transcribe models only produce text after a turn is committed, so they cannot trigger a speculative answer. The model is one constant (`wire::DEFAULT_MODEL`) and `CloudConfig::model`; there is no model picker. Revisit if its price or quality is a problem; `gpt-transcribe` ($0.0045 a minute) would need the turn gate to be short and would lose live deltas.
- **Client-side turns with an energy gate** (`gate.rs`): 20 ms windows, speech above -42 dBFS RMS, three loud windows open a turn, 300 ms of pre-roll, 700 ms of quiet commit it, 25 s forces a commit. It also keeps silence off the wire, so only speech is billed. The threshold and hangover are untested on real calls (unverified); the first real run should check that soft speech is not cut and that the pauses inside a sentence do not split turns too often.
- **One connection per speaker, one provider item per turn, one transcript segment per item.** The segment id is the turn number, every delta is a new revision (the accumulated text), `completed` is the final revision, an empty completion revokes a segment that was shown. Item ids are matched to turns in commit order because the live model reports no audio offsets; start and end come from the audio the client sent, on the sidecar clock (frame `start_ms`).
- **Resampling 16 kHz to 24 kHz** with streaming linear interpolation, pure Rust. A better filter is not needed for recognition; revisit if accuracy on sibilants is poor.
- **Credentials behind `CloudCredentials`** (`credential()` returns a bearer token and an optional expiry, read on every connect, so a reconnect gets a fresh token). `ByokOpenAi` reads the Keychain item in `spawn_blocking`. The core builds `ByokOpenAi` in `App::start` from the cached secret store; hosted mode can replace `CoreParts::cloud_credentials` (add a field to `AppConfig` when it lands). A token is only checked at the handshake, so an open socket outlives its expiry.
- **Opt-in rules.** `EnginePreference` is saved in the `settings` table (`engine_preference`), default `local`. `StartSession` with `Cloud` and no OpenAI key shows a notice and starts nothing (no helper is even spawned). With `Local`, a saved locale that the helper does not list stops the session before `Start` with a notice that points to Settings > Transcription; the system-locale-to-`en-US` fallback of the earlier locale decision is unchanged, because it only applies when the user never chose a language. The cloud is never a fallback for any failure.
- **Cloud accepts any language.** With the cloud preference `SetLocale` takes any valid BCP 47 tag and the settings view shows the chosen locale instead of the nearest installed one. The language select in the UI still lists only installed languages, so a language the Mac lacks cannot be picked from the UI yet. Revisit with the onboarding benchmark, which needs a language list for the cloud.
- **fd 3.** `SidecarProcess::spawn_with_pcm` makes a pipe and maps its write end to fd 3 in the child with the `command-fds` crate (Android and ChromeOS maintainers; it wraps `pre_exec`, so the workspace keeps `unsafe_code = "deny"`). `ProcessSidecarFactory` always opens it, since the helper is reused between sessions and the engine is only known at `StartSession`. The parent drops its copy of the write end after spawn, so the reader ends when the helper dies. `SidecarLink` gained a `pcm` field.
- **The loop routes PCM frames** (`app/event_loop/cloud.rs`): frames from the pipe go through a bounded channel (512) into the loop, which `try_send`s them to the engine's per-speaker queue (512). A refused frame is counted per speaker and added to `DebugStats::dropped_buffers` next to the helper's own count. Between the pipe and the loop a full channel blocks the reader, which backs up the pipe, as for events.
- **Reconnect once.** A dropped socket (or a failed connect that is not an authentication error) is retried once after 500 ms; a connection that lived 60 s earns the retry back, so a long meeting survives the 60 minute session limit and a few drops. On the second failure the engine reports `Unavailable`, the core stops it, shows `EngineView::Unavailable` and a notice. A 401 or 403 and a refused `session.update` are never retried. When a socket dies, the text of its unfinished turns is finalized so no line stays partial forever; audio sent into the dead socket is lost.
- **Spend.** `config/pricing.toml` has a new `[transcription."gpt-live-transcribe"]` table at $0.017 a minute of audio (both pages above, 2026-11-06; neither page states a publication date). The engine counts the milliseconds of 24 kHz audio it sent, and the loop adds that cost to `DebugStats::spend_micro_usd` once a second and when the engine stops. It does not feed the automatic-answer spend cap, which stays about model tokens (earlier decision). Two speakers talking cost twice as much per minute of wall time.
- **Not done:** there is no model picker for transcription, and the notch shows the engine only while listening (an icon in the pill, "Cloud" in the expanded bar).

### 2026-11-06 (slice 2: integration)

- **Hosted credentials.** `HostedOpenAi` asks the account task for a token (`Command::RealtimeToken`, answered on a oneshot), so the task refreshes the access token when needed and a 401 retries once. The token is returned to the caller and kept nowhere else. `FirstAvailable([ByokOpenAi, HostedOpenAi])` replaces `ByokOpenAi` in `App::start`: it moves on only when a source answers `Missing`, so a Keychain error stops the session instead of silently switching to hosted mode. Signed out, the hosted source answers `Missing` without a request. `cloud_transcription_available` is now "own key or signed in", the precheck notice names both, and the engine picker dialogs say which one will be billed. Cloud is still an explicit choice: signing in does not change `engine_preference`.
- **`fake: true` is refused** in `HostedOpenAi` (an `Unavailable` error, so the engine stops with a notice); no audio is sent with it.
- **Backend mint did not match the engine and was fixed.** It sent `transcription.language`, but `gpt-live-transcribe` takes `languages` (array) and the docs say not to send both (https://developers.openai.com/api/docs/guides/realtime-transcription). It also left `turn_detection` unset, so it now sends `turn_detection: null` like the engine. `zh` is left out of the hint, as in `wire.rs`. The endpoint (`POST /v1/realtime/client_secrets`, `session.type: "transcription"`, 24 kHz PCM, `expires_after`) matches https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets. Unverified (no paid calls): that a client secret minted this way is accepted at `wss://api.openai.com/v1/realtime?intent=transcription`, and that the minted session's settings do not conflict with the engine's `session.update`. The first real hosted run should check both. Billing for hosted minutes is not decided anywhere in the code (ADR 0005 stays open).
- **Engine preference is not synced.** Cloud is a per-device opt-in (ADR 0003), so a remote `cloud` is never applied and this device never decides the stored value: `compose` carries the server's `engine_preference` through (`"local"` for a new account). Revisit only with a confirmation flow.
- **Modes sync names and system prompts only.** Merge is per mode: the newer `updated_at` wins (server on a tie), compared across device clocks like the settings. Deletions travel as tombstones, which needed one additive contract change: `SyncedMode.deleted` (default false, omitted when false); the backend rejects a tombstone that keeps a prompt. Tombstones leave the document after 30 days, so a device offline longer can bring a deleted mode back. Remote modes are validated like the create-mode intent (name 1 to 80 characters, no control characters, prompt at most 8,000) and ids must be UUIDs; others are skipped locally but stay in the document, because `compose` keeps server modes this device does not know. The local limit is 50 modes. Files and paths never leave the device. A mode prompt from another device goes into the system prompt, which is acceptable only because it comes from the same account.
- **Preferences body limit raised from 64 KiB to 512 KiB** (`MAX_PREFERENCES_BODY_BYTES`): 50 modes of 8,000 characters would not fit in 64 KiB and sync would fail with 413.
- **Onboarding hint.** The "Cloud transcription can be turned on in Settings > Transcription" text in `CheckAdvice` now has an "Open Settings" button in onboarding that dispatches `open_settings`. The settings window opens on its default page, so the text still names the page. Nothing enables cloud.
